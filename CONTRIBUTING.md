# Contributing

Thanks for contributing to APPLAYLIST.

## Before you start

- Open an issue for substantial behavior changes, architecture changes, or new external integrations.
- Keep changes narrowly scoped and avoid unrelated refactors.
- Never commit credentials, secrets, production data, licensed media, or personal data.
- Preserve the project's local-first and explainable-analysis boundaries unless a reviewed design explicitly changes them.

## Development

Use the environment and commands documented in the repository. Install dependencies from the lockfile, run the available checks, and verify affected workflows locally before opening a pull request.

## Pull requests

Explain what changed, why it changed, how it was tested, and any compatibility, data, licensing, or security impact. Keep generated files and unrelated formatting churn out of the diff.

By contributing, you agree that your contribution is submitted under the repository's existing proprietary license and project terms unless a separate written agreement applies.
